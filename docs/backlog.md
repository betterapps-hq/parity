# Backlog

Every piece of planned work for Parity, gathered from all the docs on 2026-10-28, for sessions to pick up. Keep it
current: it's only useful while it's true. What's decided goes in [decisions.md](decisions.md), designs in
[proposals](proposals), and what works in [support.md](support.md).

## How sessions use it

1. **Read it before starting work** in `D:\canvas`, and check In progress so two sessions don't take related work.
2. **Pick** the first Ready item in Up next, or else the first Ready item in a stream. Each item should fit one session;
   split a bigger one into new items first.
3. **Claim it before writing code.** Re-read this file, since others edit it, then set the item's Status to
   `In progress: <your session's title>`, add it to In progress, and save.
4. **Finish:** run `pnpm verify`, then move the item's row to Done with the date and your session, and take its ID out
   of other items' `After` lists, setting any that empty to Ready. Update the rows it changes in support.md, ask the
   Design Editor session to republish the support matrix, and record any calls you made in decisions.md.
5. **Found more work?** Add it to its stream with the next free ID, as a row with a Done when. IDs are permanent: never
   renumber or reuse one.
6. **Blocked by a decision?** Add it to Waiting on you if it's new, and set the item's Status to `Waiting on you: Q<n>`.
   Questions go to the user, not into the code. When the user answers, record the answer in decisions.md, delete the
   question's row, and update the items it blocked.
7. **Statuses:** Ready (nothing it needs is unfinished), `After <IDs>` (those items first), In progress, Waiting on you,
   Later (the user put it after the core), Parked (React and Vite only). Finished items move to Done. Sizes: S is a
   short session, M a full one, L a full one with little slack.
