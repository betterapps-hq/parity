# Design options: every CSS property and where it goes

Part of [design-options.md](design-options.md) (PAR-652). This page places each CSS property a frame can draw in the
Design tab, so the panel's coverage can be checked property by property rather than by feel.

**The ledger is data now (PAR-940).** `packages/style/src/placements.ts` holds the placing in the tables below, and
`spec.json` beside it the property list, each property's grammar and its Baseline status, generated from `@webref/css`
and `web-features`. `ledger.ts` joins them, and its tests fail when a property Chromium draws isn't placed exactly once.
Change a placing there; this page describes it.

## What's counted

Every standard CSS property that Chromium 156 draws without a prefix, since frames render in Parity's Electron 45.2.1,
which ships Chromium 156. That's 562 properties, from MDN's browser compatibility data (8.1.8, 2 November 2026) joined
with the W3C's list of every property and its spec. Deprecated properties aren't counted: the `-webkit-box-*` family,
`clip`, `page-break-*`, `text-decoration-skip` and `user-modify`.

Where each one goes:

| Where    | Properties | What it means                                                                                                                                                                                                           |
| -------- | ---------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Control  |        248 | Its own control in a section, shown whenever the section applies to what's selected, or, for a row the layer rarely needs, once it's set ([design-options-panel.md](design-options-panel.md), intro)                    |
| More     |        191 | Listed under the section's More, and shown as a row once it's set                                                                                                                                                       |
| CSS row  |         85 | Typed into the CSS row at the end of the Design tab, which takes any declaration and checks it                                                                                                                          |
| Left out |         38 | No control and no More entry: SVG geometry, which belongs in the SVG's own file, speech, MathML, `all`, which resets every property a control owns, and two that the browser or Electron set (`overlay`, `window-drag`) |

Read this page to check coverage, not to learn the panel; the panel page is the design.

The CSS row takes the left-out ones too, except `all`, so nothing else a frame can draw is out of reach. A property's
longhands, shorthand and logical forms are one concept with one control: Padding writes `padding`, its four sides or its
logical sides, whichever the layer already uses. A family's longhands go where its shorthand goes, so a long family is
listed as its shorthand and a glob with a count (`border-*` is every `border-` property not named in another row); the
glob's count is checked against the 562.

Marks after a name say how widely browsers other than Chromium draw it, from the web-features project's Baseline:

- No mark: Baseline, widely available (387 of the 562).
- ‡ Baseline, newly available: every major browser, but only in the last two and a half years (46).
- † Not Baseline: Chromium has it and at least one other major browser doesn't yet (129, the six below among them). The
  panel marks these, as principle 7 in [design-options.md](design-options.md) says. A glob's mark applies to every
  property it covers.

Six have no Baseline entry yet: `background-repeat-x`, `background-repeat-y`, `caret-animation`, `flex-line-count`,
`text-decoration-inset` and `view-transition-group`. These have no Baseline status; each is missing from at least one
other major browser (only Chromium draws `caret-animation`, `flex-line-count` and `view-transition-group`), so each is
marked † by principle 7.

## Prefixed properties people still use

Chromium also draws some prefixed or non-standard properties that designs use often enough to place.

| Property                                                                        | Where         | Why                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `-webkit-line-clamp` with `-webkit-box-orient`                                  | Text, Control | Max lines writes what Tailwind's `line-clamp-N` writes (`overflow: hidden; display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: N`), as render.ts does today. ## Properties set by another control

A control can set a property another control owns when it needs it (principle 8 in
[design-options.md](design-options.md)). The owning control then shows that value as set by the other one ("0, set by
Fill"), and changing it there turns the other control to Custom. This table is the one list of these pairs.

| Control                            | Sets                                                                                                                                                                                         | Owned by                                                  |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Fill (Width or Height)             | `min-width` or `min-height: 0`, and `align-self: stretch`, or `width: 100%` with a max on that axis                                                                                          | Min and max, Align self, Width                            |
| Truncate                           | `overflow`, `display`, `white-space`, `text-overflow`, and a Fixed width on Auto width text                                                                                                  | Clip content, Layout type, Wrap, Width                    |
| Layer order                        | `position: relative`, only in a Block layout                                                                                                                                                 | Placement                                                 |
| Position's Center preset           | `margin-inline` or `margin-block: auto`, and `width: fit-content` when the width is Hug                                                                                                      | Margin, Width                                             |
| Text's gradient Color              | `background-image`, `background-clip`                                                                                                                                                        | Fill                                                      |
| Stroke's gradient color            | `background-image`, `background-clip` and `background-origin` (the fills to `padding-box`, the gradient to `border-box` under them), the bottom fill as a layer, `border-color: transparent` | Fill, Stroke's Color                                      |
| Aspect ratio                       | The other axis's size, which it writes nothing on; `align-self: flex-start` in a flex layout that stretches its children                                                                     | Width, Height, Align self                                 |
| Size container                     | A Hug width, made Fill                                                                                                                                                                       | Width                                                     |
| Placement Absolute                 | `position: relative` on the parent layout, where it needs it ([design-options-code.md](design-options-code.md), Frames add only what code writes)                                            | The parent's Placement                                    |
| Freeform                           | Each child's `position: absolute` and insets, and `position: relative` on the layout                                                                                                         | Each child's Placement and Insets, the layout's Placement |
| Visibility (Removed in some modes) | `display: none`, and the layer's own display where it shows                                                                                                                                  | Layout type                                               |
| Dividers, On the items             | The children's `border-*-width`, `border-style` and `border-color`                                                                                                                           | Each child's Stroke                                       |
| Stacking, First on top             | Descending `z-index` on the children                                                                                                                                                         | Each child's Layer order                                  |
| Gap, negative                      | Each child's `margin-inline-start` and `margin-inline-end`, or the block pair (`-space-x-*`, `-space-y-*`)                                                                                   | Each child's Margin                                       |

## How the ledger was made

A script joined MDN's `@mdn/browser-compat-data` (`css.properties`, Chrome's `version_added`, unprefixed and without a
flag), the web-features project's Baseline status by compat key, and the W3C's
[list of all CSS properties](https://www.w3.org/Style/CSS/all-properties.en.html), then checked that each of the 562 was
placed exactly once.

Since PAR-940 the join is `packages/style/src/spec.test.ts`, which writes `spec.json` from two packages: `web-features`
for the properties Chromium 156 draws (each compat key's Chrome version) and their Baseline status, and `@webref/css`,
the W3C's spec data, for each property's value grammar. It lists the same 562, naming the 15 that web-features has no
entry for yet, and with them the ten prefixed properties from the table above, 572 in all. When Electron moves to a
newer Chromium, change `chromium` there and run it with `-u`: the ledger's test then fails until each property that
shipped in between is given a place in `placements.ts`, the CSS row's if nothing better.
