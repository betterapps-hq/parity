Accessibility considerations for special characters

Screen readers skip over some symbols and other nonalphabetic characters without reading
them or indicating their presence. This situation can cause accessibility problems:

      Users of a document or webpage lack important information.
      Users of a website or web app can't determine the purpose of buttons and other UI
      elements.

Be aware of this possibility whenever you write content that users will access in electronic form.
Consider the following solutions.

General approaches

Whenever you can, write out the words that you mean instead of using special characters. For
example, write "1 through 10" instead of "1–10."

If you must use special characters, use the correct character for the purpose, as outlined in the
preceding table. For example, unless you must match what appears in the UI, use a
multiplication sign (×) instead of an asterisk (*) or the letter x to represent a multiplication
operation.

Content in HTML and related formats: Character entity
references

In content written in HTML or a related language (including Markdown), you can improve the
accessibility of some special characters by inserting a character entity reference instead of the

character itself. This type of reference begins with an ampersand (&) and ends with a
semicolon (;).

For example, for a copyright symbol, you can enter              &copy;    instead of the symbol in your code.
A screen reader that skips over the symbol itself should read out something like "copyright" for
the entity reference, giving users information that they would otherwise lack.

However, because of the way screen readers work, the use of entity references for all special
characters doesn't necessarily yield a better user experience.

UI elements:             aria-label            attributes

For UI elements, such as for a website or web app, an alternative to character entity references
is the aria-label     attribute. This attribute is part of Web Accessibility Initiative - Accessible Rich
Internet Applications (WAI-ARIA). WAI-ARIA is a set of roles and attributes that define ways to
make web content and web applications more accessible to people with disabilities.

The  aria-label     attribute is applicable only to:

      Interactive elements, such as buttons, text boxes, and checkboxes.
      Images.
      So-called landmarks, such as a page's header, footer, menu, and main content area.

It isn't intended—or widely supported—for static, non-UI textual content.

If the label text of an applicable UI element includes a special character from the preceding
table, but you're not using the specified entity reference, add an               aria-label     attribute to the
element to improve accessibility. A screen reader will then read out the attribute's value instead
of the element's label text.

The value that you provide for the attribute should give the full name of the element, including
the name of the special character as it should be read.

Example

to handle this situation:

      Character entity reference in label text:         <button>90&deg;</button>

Character in label text,      aria-label     on element:     <button aria-label="90

      degrees">90°</button>

This section covers usage and abbreviations for a variety of terms related to
measurement. For other units of measure not covered here, see The Chicago Manual of
Style   .

      Use numerals for measurements of distance, temperature, volume, size, weight,
      pixels, points, and so on—even if the number is less than 10. Add a zero before the
      decimal point for decimal fractions less than one, unless the customer is asked to
      enter the value.

      Examples
      3 ft, 5 in.
      1.76 lb
      80 × 80 pixels
      0.75 grams
      enter .75"
      3 centimeters
      3 cm

      Insert a space between the unit of measure and the numeral, or hyphenate if the
      measurement modifies a noun.

      Examples
      13.5 inches
      13.5-inch display
      8.0 MP
      8.0-MP camera

      Use abbreviations only with numbers in specific measurements, such as 20 MP, and
      don't follow the abbreviation with a period.

      Exception Follow in with a period when used as an abbreviation for inch.

      Use commas in numbers that have four or more digits, regardless of how the
      numbers appear in the UI: 1,093 MB.

      Exceptions
      For years, pixels, and baud use commas only when the number has five or more
      digits: 1920 × 1080 pixels, 10,240 × 4320 pixels, 9600 baud, 14,400 baud.
      Don't use commas after the decimal point in decimal fractions.
